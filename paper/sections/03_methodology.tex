\section{Methodology}
\label{sec:methodology}

\subsection{Overview}

Given a C/C++ function $f$, VulGCL produces a binary vulnerability label
$\hat{y} \in \{0,1\}$ by fusing three independently derived representations:

\begin{equation}
\hat{y} = \sigma\!\left(
  \text{MLP}\!\left(\mathbf{h}_G \,\|\, \mathbf{h}_I \,\|\, \mathbf{h}_L\right)
\right)
\end{equation}

where $\mathbf{h}_G \in \mathbb{R}^{256}$, $\mathbf{h}_I \in \mathbb{R}^{256}$,
and $\mathbf{h}_L \in \mathbb{R}^{256}$ are the graph, image, and LLM branch
embeddings respectively, and $\|$ denotes vector concatenation.
Each branch derives its input from a different structural view of the same
Program Dependency Graph, ensuring the three representations carry complementary
rather than redundant information. Figure~\ref{fig:architecture} illustrates
the full pipeline.

\begin{figure*}[t]
  \centering
  \includegraphics[width=\textwidth]{../docs/figures/fig03_architecture.png}
  \caption{VulGCL architecture. A C/C++ function is parsed into a PDG by Joern,
    which is then processed by three independent branches: a GAT-based graph
    branch ($\mathbf{h}_G$), a centrality-image CNN branch ($\mathbf{h}_I$), and
    a CodeBERT LLM branch on a betweenness-guided slice ($\mathbf{h}_L$). A
    learned softmax gate fuses the three 256-dim embeddings, and a two-layer MLP
    produces the vulnerability probability.}
  \label{fig:architecture}
\end{figure*}

% ── PDG Extraction ────────────────────────────────────────────────────────────
\subsection{PDG Extraction}
\label{sec:pdg}

We parse each function using Joern~\cite{joern}, an open-source static
analysis framework, to extract its Program Dependency Graph
$\mathcal{G} = (\mathcal{V}, \mathcal{E})$. Each node $v_i \in \mathcal{V}$
represents a single code statement; each directed edge
$e_{ij} \in \mathcal{E}$ encodes a data or control dependency from statement
$i$ to statement $j$, annotated with the variable $\phi_{ij}$ carrying the
dependency. Joern handles real-world C/C++ constructs including macros,
typedefs, and platform-specific APIs. All three branches derive their inputs
from $\mathcal{G}$, as described below. Figure~\ref{fig:pdg} shows an example
PDG extracted from a buffer-overflow function and the resulting node table.

\begin{figure*}[t]
  \centering
  \includegraphics[width=\textwidth]{../docs/figures/fig04_pdg_extraction.png}
  \caption{PDG extraction. Joern performs static analysis on the C source function
    (left) and produces a Program Dependency Graph (right) where solid blue edges
    denote data dependencies and dashed orange edges denote control dependencies.
    The node table (bottom) shows the statement type for each PDG node; node~3
    (\texttt{buffer[x]=0;}) is the vulnerable assignment.}
  \label{fig:pdg}
\end{figure*}

% ── Graph Branch ──────────────────────────────────────────────────────────────
\subsection{Graph Branch ($\mathbf{h}_G$)}
\label{sec:graph_branch}

The graph branch captures the \emph{structural dependency topology} of the
function---which statements affect which others, and through which variables.

\paragraph{Node features.}
Each node $v_i$ is initialized with a 768-dimensional CodeBERT
embedding~\cite{codebert} of its code statement:
$\mathbf{x}_i = \text{CodeBERT}(v_i.\text{code})[\texttt{CLS}] \in \mathbb{R}^{768}$.
These embeddings are shared with the image branch
(Section~\ref{sec:image_branch}), so CodeBERT runs \emph{once} per function
during preprocessing.

\paragraph{Graph Attention Network.}
The node feature matrix $\mathbf{X} \in \mathbb{R}^{|\mathcal{V}| \times 768}$
is passed through two layers of a Graph Attention Network
(GAT)~\cite{gat2018}, a GNN variant that learns per-edge attention weights
rather than treating all neighbors equally. This is important for PDG-based
vulnerability detection: not all data dependencies carry equal risk, and
attention allows the model to focus on the most dangerous dependency paths.
Each attention head computes:
\begin{equation}
\alpha_{ij} = \frac{
  \exp\!\left(\text{LeakyReLU}\!\left(\mathbf{a}^\top
    [\mathbf{W}\mathbf{x}_i \,\|\, \mathbf{W}\mathbf{x}_j]\right)\right)
}{
  \sum_{k \in \mathcal{N}(i)} \exp\!\left(\text{LeakyReLU}\!\left(\mathbf{a}^\top
    [\mathbf{W}\mathbf{x}_i \,\|\, \mathbf{W}\mathbf{x}_k]\right)\right)
}
\end{equation}
We use 4 attention heads, hidden dimension 256, and global mean pooling:
\begin{equation}
\mathbf{h}_G = \text{MeanPool}\!\left(\text{GAT}^{(2)}(\mathbf{X},\,\mathcal{E})\right)
\in \mathbb{R}^{256}
\end{equation}

Figure~\ref{fig:graph_branch} illustrates the graph branch: the input PDG (left)
is transformed by two GAT layers whose learned attention weights $\alpha_{ij}$
(right) reflect the relative importance of each dependency edge.

  \caption{Graph branch. The input PDG (left) carries structural node features

% ── Image Branch ──────────────────────────────────────────────────────────────
\subsection{Image Branch ($\mathbf{h}_I$)}
\label{sec:image_branch}

The image branch encodes the \emph{visual structural pattern} of the function
as a three-channel matrix image, inspired by VulCNN~\cite{vulcnn}. Our
key improvement over VulCNN is replacing sent2vec with CodeBERT node embeddings,
enabling richer code semantics in the visual representation.

\paragraph{Centrality-weighted image construction.}
For each node $v_i$, we compute three PDG centrality scores:
degree centrality $\kappa_{\text{deg}}(v_i)$,
Katz centrality $\kappa_{\text{katz}}(v_i)$, and
closeness centrality $\kappa_{\text{clo}}(v_i)$.
The three-channel image is constructed as:
\begin{equation}
\mathbf{I}_{i,\cdot,c} = \kappa_c(v_i) \cdot \mathbf{x}_i,
\quad c \in \{1,2,3\}
\end{equation}
where $\mathbf{x}_i \in \mathbb{R}^{768}$ is the shared CodeBERT node
embedding. The tensor
$\mathbf{I} \in \mathbb{R}^{|\mathcal{V}| \times 768 \times 3}$
is resized to $100 \times 100 \times 3$ via bilinear interpolation.

\paragraph{CNN encoder.}
Five convolutional layers with batch normalization and ReLU activations,
followed by global average pooling:
\begin{equation}
\mathbf{h}_I = \text{GAP}\!\left(\text{CNN}(\mathbf{I})\right) \in \mathbb{R}^{256}
\end{equation}

Figure~\ref{fig:image_branch} shows the image branch pipeline from centrality
score table to three-channel pixel grid to CNN encoding.

\begin{figure*}[t]
  \centering
  \includegraphics[width=\textwidth]{../docs/figures/fig06_image_branch.png}
  \caption{Image branch. PDG node centrality scores (left table) are multiplied
    by the shared CodeBERT node embeddings to form a three-channel
    $100{\times}100$ image (center, channels: degree, closeness, Katz). A
    three-layer CNN with batch normalization and global average pooling encodes
    the image into $\mathbf{h}_I \in \mathbb{R}^{256}$.}
  \label{fig:image_branch}
\end{figure*}

% ── LLM Branch ────────────────────────────────────────────────────────────────
\subsection{LLM Branch ($\mathbf{h}_L$)}
\label{sec:llm_branch}

The LLM branch captures the \emph{semantic meaning} of the most structurally
critical statements. Feeding the full function text to CodeBERT would overlap
with the node-level semantics already encoded in the graph and image branches.
Instead, we construct a focused \emph{PDG-guided slice} that targets the
statements where vulnerabilities most commonly reside.

\paragraph{PDG-guided slice construction.}
We rank all nodes by betweenness centrality on $\mathcal{G}$:
\begin{equation}
\beta(v) = \sum_{s \neq v \neq t} \frac{\sigma_{st}(v)}{\sigma_{st}}
\end{equation}
where $\sigma_{st}$ is the total number of shortest paths from $s$ to $t$
and $\sigma_{st}(v)$ is the number passing through $v$. The top-$K$ nodes
by $\beta$ are sorted by source line number and concatenated to form the
slice $S_f$. We use $K=10$, keeping the slice within CodeBERT's 512-token
limit.

\paragraph{CodeBERT fine-tuning.}
The slice $S_f$ is tokenized and passed through CodeBERT~\cite{codebert},
a RoBERTa-base model pre-trained on 6M (code, comment) pairs across six
programming languages. The \texttt{[CLS]} token is projected to:
\begin{equation}
\mathbf{h}_L = W_L \cdot \text{CodeBERT}(S_f)[\texttt{CLS}] + b_L,
\quad W_L \in \mathbb{R}^{256 \times 768}
\end{equation}
CodeBERT weights are fine-tuned end-to-end jointly with the rest of the model.
Figure~\ref{fig:llm_branch} illustrates the LLM branch pipeline.

\begin{figure*}[t]
  \centering
  \includegraphics[width=\textwidth]{../docs/figures/fig07_llm_branch.png}
  \caption{LLM branch. PDG nodes are ranked by betweenness centrality (left bar

    BPE-tokenized and passed through fine-tuned CodeBERT; the \texttt{[CLS]}
    token is projected via a linear layer to
    $\mathbf{h}_L \in \mathbb{R}^{256}$.}

\end{figure*}

% ── Fusion ────────────────────────────────────────────────────────────────────
\subsection{Fusion and Classification}
\label{sec:fusion}

The three 256-dimensional embeddings are concatenated to a 768-dimensional
vector and passed through a two-layer MLP with dropout ($p=0.3$):

\begin{equation}
\hat{y} = \sigma\!\left(W_2 \cdot \text{ReLU}\!\left(
  W_1 \cdot [\mathbf{h}_G \| \mathbf{h}_I \| \mathbf{h}_L] + b_1
\right) + b_2\right)
\end{equation}

where $W_1 \in \mathbb{R}^{256 \times 768}$ and $W_2 \in \mathbb{R}^{1 \times 256}$.
We optimize binary cross-entropy loss with AdamW, linear warmup over the first
epoch, and cosine decay scheduling. Figure~\ref{fig:fusion} summarizes the full
fusion mechanism.

\begin{figure*}[t]
  \centering
  \includegraphics[width=\textwidth]{../docs/figures/fig08_fusion.png}
  \caption{Gated fusion and classification. The three branch embeddings
    $\mathbf{h}_G$, $\mathbf{h}_I$, $\mathbf{h}_L$ are fed to a learned softmax
    gate (center) that produces per-branch weights (stacked bar: Graph~52\%,
    Image~11\%, LLM~37\% in this example). The weighted sum is passed through a
    two-layer MLP to produce the vulnerability probability $\hat{y}$.}
