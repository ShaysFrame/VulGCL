\section{Experiments}
\label{sec:experiments}

\subsection{Research Questions}

\begin{itemize}
  \item \textbf{RQ1:} Does VulGCL outperform single-modality baselines on AUC and F1?
  \item \textbf{RQ2:} Does each branch contribute? (single-branch ablation)
  \item \textbf{RQ3 (future):} Which GNN architecture works best for the graph branch?
  \item \textbf{RQ4 (future):} What is VulGCL-Lite's accuracy-latency tradeoff on edge hardware?
\end{itemize}

\subsection{Dataset and Evaluation Protocol}

We evaluate on \textbf{Devign}~\cite{devign}, a widely-used C/C++ vulnerability detection
benchmark comprising 27,318 real-world functions drawn from four open-source projects:
FFmpeg, QEMU, LibTIFF, and VLC. Labels are derived from security-relevant commit history
(fix commits vs.\ clean commits); functions are not individually CVE-verified.
The dataset is split into training (21,854), validation (2,732), and test (2,732)
sets, with approximately 45\% vulnerable functions — nearly balanced, so no class
weighting is required.

Program dependency graphs are extracted via Joern~\cite{joern}. Joern fails to parse
approximately 6\% of Devign functions (syntactically unusual or heavily
macro-expanded code); such functions are excluded, yielding a usable fraction of
$\approx$94\%.

We report two primary metrics. \textbf{AUC-ROC} (Area Under the Receiver Operating
Characteristic curve) is our primary evaluation metric, as it is threshold-independent
and reflects the model's ranking ability across all operating points.
\textbf{F1 score} is reported as a secondary metric, computed at the threshold
that maximises F1 on the validation set via a grid search over $[0.10, 0.89]$ in
steps of 0.01.

Figure~\ref{fig:dataset} summarizes the Devign dataset split and class balance.

\textbf{Training details.} All models are trained for up to 20 epochs with early
stopping (patience\,=\,3) by validation AUC. Optimiser: AdamW with linear warmup
(500 steps) followed by cosine decay; backbone learning rate $2\times10^{-5}$,
head learning rate $2\times10^{-4}$; batch size 32; gradient clipping at 1.0.
Training was performed on an NVIDIA L20 GPU (fp16 mixed precision).

\subsection{Baselines}

We compare against three published single-modality detectors evaluated on Devign:

\begin{itemize}
  \item \textbf{Devign / IVDetect}~\cite{devign,ivdetect}: GNN-based methods that
    apply graph convolutions over code property graphs. Representative of the
    graph-only paradigm.
  \item \textbf{VulCNN}~\cite{vulcnn}: Converts PDG centrality features into a
    two-dimensional image and classifies it with a CNN. Representative of the
    image-only paradigm.
  \item \textbf{LineVul}~\cite{linevul}: Fine-tunes CodeBERT on the raw function
    text for line-level vulnerability detection. Representative of the LLM-only
    paradigm and the strongest published single-modality baseline on Devign.
\end{itemize}

Published F1 scores are taken directly from the respective papers; AUC values are
not uniformly reported across these baselines, so comparisons on AUC are made only
among our own controlled ablations.

\textbf{Comparison to published baselines (Table~\ref{tab:main_results}).}
VulGCL achieves F1\,=\,0.653, the highest among all compared methods.
The margin over LineVul (0.651) is narrow ($+$0.002), reflecting that
LineVul's CodeBERT fine-tuning is already a strong baseline. Note that
published scores were obtained under each paper's own preprocessing pipeline
and data split; a controlled reproduction on a unified split is left for future work.

\textbf{Ablation and AUC analysis (Table~\ref{tab:ablation}).}
AUC is adopted as the primary metric because it is threshold-independent.
VulGCL achieves AUC\,=\,0.669, exceeding all single-branch variants.
The LLM-only branch is the strongest single modality (AUC\,=\,0.659),
reflecting the power of CodeBERT's semantic pre-training. The full fusion
adds $+$1.07 percentage points over LLM only, confirming that graph structural
and visual centrality signals carry complementary discriminative information.
Although LLM only achieves slightly higher F1 (0.663 vs.\ 0.653), this
arises from threshold sensitivity: LLM only selects threshold 0.25
(recall-heavy on the near-balanced dataset), while VulGCL selects 0.29.
AUC removes this threshold artefact and is the honest verdict.

\subsection{Results — RQ2: Ablation Study}

Table~\ref{tab:ablation} shows single-branch ablations.

\begin{table}[t]
\centering
\small
\caption{Ablation study on Devign. AUC is the primary metric.
Best value per column is \textbf{bold}.}
\label{tab:ablation}
\begin{tabular}{lcc}
\toprule
Configuration & F1 & AUC \\
\midrule
Graph only              & 0.630 & 0.573 \\
Image only              & 0.625 & 0.572 \\
LLM only                & \textbf{0.663} & 0.659 \\
\textbf{VulGCL (full)}  & 0.653 & \textbf{0.669} \\
\bottomrule
\end{tabular}
\end{table}

Each branch individually degrades below the full model on AUC (the primary metric).
The LLM branch is the dominant contributor — its standalone AUC (0.659) is much
higher than graph (0.573) or image (0.572), reflecting the power of semantic
pre-training. Nevertheless, the full three-branch fusion exceeds even the LLM branch
alone on both AUC and accuracy, confirming that graph structural information and
visual centrality patterns provide complementary signal.

Two-branch ablations (Graph+LLM, Image+LLM, Graph+Image) are left for future work.

\subsection{Results — RQ3 and RQ4: Future Work}

\textbf{RQ3: GNN architecture comparison.}
A comparison of GCN, GAT, GraphSAGE, and GIN within the graph branch is planned for
the extended version of this work. Based on our methodology, GAT is expected to
outperform GCN and GraphSAGE due to its learned attention weights per edge, which
align with the semantics of data and control dependencies.

\textbf{RQ4: Edge deployment (VulGCL-Lite).}
A quantized VulGCL-Lite variant designed for Raspberry Pi 4B and similar
resource-constrained devices is planned as a follow-on contribution. The goal is to
enable real-time vulnerability scanning at the embedded build stage. Preliminary
design targets: $\leq$200\,ms per function, $\leq$512\,MB RAM, with $\leq$3\%
accuracy drop relative to the full model.
