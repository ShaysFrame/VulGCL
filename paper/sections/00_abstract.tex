Automated vulnerability detection in source code is critical for software
security. Existing approaches fall into two camps: image-based methods
(e.g., VulCNN, VulGAI) that convert code into visual representations for
CNN classification — fast but losing structural relationships — and graph-based
methods (e.g., ReGVD, iGnnVD) that apply graph neural networks (GNNs) over
code graphs — accurate but ignoring visual and semantic signals. No prior work
unifies all three modalities for general source-code vulnerability detection.

We present \textbf{VulGCL}, a multimodal vulnerability detection framework that
jointly learns from three complementary views of a code function: (1)~a
\emph{graph branch} that applies a GNN over the Program Dependency Graph (PDG)
to capture structural relationships; (2)~an \emph{image branch} that converts
the PDG into a three-channel image via node centrality encoding and applies a
CNN to capture visual patterns; and (3)~an \emph{LLM branch} that fine-tunes
CodeBERT on a betweenness-centrality-guided code slice to capture the semantic
meaning of critical statements. The three representations are fused by a learned
softmax gate and passed to an MLP classifier. Per-branch auxiliary losses during
training prevent the dominant LLM branch from suppressing structural signals.

Experiments on the Devign benchmark (27,318 C/C++ functions with
security-commit-derived labels) show that VulGCL achieves an AUC-ROC of 66.9\%
and F1 of 65.3\% on the test set. AUC is adopted as the primary evaluation
metric because it is threshold-independent and reflects the model's discriminative
ranking ability across all operating points. The three-branch fusion outperforms
all single-modality variants on AUC, exceeding the strongest single branch
(LLM only, AUC\,=\,65.9\%) by $+$1.07 percentage points, confirming that graph
structural and visual centrality signals carry complementary information beyond
semantic pre-training alone. Two-branch ablations, cross-dataset evaluation on
BigVul, and a quantized edge variant (VulGCL-Lite) for resource-constrained
deployment are planned for the extended version of this work.
